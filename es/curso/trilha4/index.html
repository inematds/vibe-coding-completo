4.1 ~50 min · 7 temas

📦 Skills: concepto y anatomía

La skill es un workflow en Markdown que invocas como slash command. Aquí: qué es, dónde está (.claude/skills), la anatomía del SKILL.md, cómo las skills llaman a las tools, cuándo usar una skill o escribir directamente, skills vs. CLAUDE.md y cómo compartirlas y versionarlas.

Progreso del módulo 0% · 0 de 7
Qué es:

Un archivo Markdown con instrucciones: conceptualmente, lo mismo que un «workflow» (la capa W de WAT), pero guardado en un directorio especial y expuesto como slash command.

Por qué aprender:

Dejas de volver a explicar la misma tarea: el proceso se vuelve invocable y consistente.

Conceptos clave:

Skill = workflow invocable; markdown; el mismo proceso cada vez.

Qué es:

Cada skill vive en su propia carpeta dentro de .claude/skills, con un archivo markdown que la define; entonces aparece como un slash command (p. ej.: /draft-email).

Por qué aprender:

Es cómo el agente «descubre» la skill y la expone para que la invoques.

Conceptos clave:

Una carpeta por skill; los slash commands se convirtieron en skills; descubrimiento automático.

Qué es:

O SKILL.md define el nombre, la descripción (cuándo activarla), los argumentos esperados y las instrucciones paso a paso.

Por qué aprender:

La descripción es lo que le indica al agente CUÁNDO usar la skill; los argumentos son lo que te pide.

Conceptos clave:

Nombre; descripción que activa; argumentos; pasos.

Qué es:

Una skill todavía puede activar tools (scripts de Python: búsqueda web, scraping, generación de documentos); el framework WAT permanece intacto por debajo.

Por qué aprender:

Una skill no es solo texto: es un proceso que ejecuta trabajo real mediante tools.

Conceptos clave:

Skill ≈ W; tools ≈ T; el agente decide cuándo ejecutar cada tool.

Qué es:

Usa una skill para workflows repetidos, cuando la consistencia importa o para instrucciones complejas o fáciles de olvidar. Para una tarea de una frase o un experimento único, solo escribe: usar una skill sería exagerado.

Por qué aprender:

Saber cuándo empaquetar evita tanto el caos como el over-engineering.

Conceptos clave:

Repetición → skill; algo puntual → escribir; consistencia; compartir.

Qué es:

CLAUDE.md guarda solo las reglas de todas las sesiones (propósito, objetivo, framework); las instrucciones por tarea van en skills, que se cargan bajo demanda solo cuando se invocan.

Por qué aprender:

Poner todo en CLAUDE.md desborda la ventana de contexto; las skills ahorran tokens.

Conceptos clave:

Cada sesión frente a bajo demanda; 20-50 skills no aumentan el tamaño; ventana de contexto.

Qué es:

Como la skill es un archivo en la carpeta del proyecto, se puede versionar en Git y compartir con el equipo; todos obtienen el mismo proceso confiable.

Por qué aprender:

Una skill probada en la práctica se convierte en un activo del equipo, no en conocimiento atrapado en una cabeza.

Conceptos clave:

Archivo = versionable; compartible; delegar y olvidar.

🔨 Construcción práctica de Skills

Manos a la obra: pedir una skill en el formato oficial, crear y probar la skill "redactar correo electrónico" (/draft-email), invocarla sin argumentos, reutilizarla con contexto limpio, crear la skill «documento → diapositivas», conectar una skill de diseño lista para usar y crear tu biblioteca de skills.

Progreso del módulo 0% · 0 de 7
Qué es:

No necesitas saber escribir skills: describes el workflow (entradas, comportamiento, dónde guardar) y le pides al agente que lo convierta en un slash command siguiendo el formato oficial.

Por qué aprender:

La misma mentalidad de vibe coding: describe el resultado y la IA genera la skill.

Conceptos clave:

Formato oficial; Plan Mode; describir las entradas/salida.

Qué es:

La primera build: una skill que recibe viñetas, destinatario y tono, y redacta un correo pulido, conciso y sin rodeos, guardándolo en la carpeta temporal. Se convierte en el slash command /draft-email.

Por qué aprender:

Es el ejemplo canónico de una skill reutilizable de principio a fin.

Conceptos clave:

Argumentos (viñetas/destinatario/tono); SKILL.md; carpeta temporal.

Qué es:

Si llamas al comando slash sin pasar datos, el agente te preguntará por los datos que faltan (destinatario, tono, viñetas) antes de ejecutarlo.

Por qué aprender:

La skill es robusta: nunca funciona "a ciegas"; recopila lo necesario.

Conceptos clave:

Recopilación de datos de entrada; argumentos faltantes; experiencia guiada.

Qué es:

Para volver a usarlo, limpias la conversación (/clear) y vuelve a llamar al slash command con nuevas entradas: una salida fresca y consistente que siempre sigue las mismas reglas.

Por qué aprender:

Contexto limpio = ejecuciones predecibles; la skill garantiza el mismo estándar.

Conceptos clave:

Limpiar entre usos; mantener la consistencia; para modificarlo, solo tienes que pedirlo.

Qué es:

Una segunda skill que lee un documento, extrae los puntos clave y crea una presentación profesional, usando tools Python por debajo.

Por qué aprender:

Muestra cómo la skill resume contenido extenso en un deck estructurado y reutilizable.

Conceptos clave:

Resumir → estructurar; herramientas de generación; iterar el diseño.

Qué es:

Integrar una skill de diseño ya existente mejora la calidad visual sin que tengas que describir manualmente cada detalle del diseño.

Por qué aprender:

Las skills se componen: superpones una skill de diseño a tu workflow.

Conceptos clave:

Composición de skills; skill de diseño; reutilización de conocimiento listo para usar.

Qué es:

Un catálogo de ideas de skills listas para que las armes: notas → acciones, datos → PDF, correo electrónico, resumen de reunión, brief de investigación.

Por qué aprender:

Te da puntos de partida concretos para construir tu propia biblioteca.

Conceptos clave:

Catálogo; skills probadas en la práctica; guardar lo que funciona.

🤖 Agentes: locales, programados y por evento

El salto a sistemas que deciden por sí solos: qué es un agente (razona, se adapta, se autocorrige), agente local bajo demanda, el ciclo de automejora, agente programado (cron), agente por evento (webhook), el agentic gap, diseñar para producción desde el 1.er prompt y cuándo un «agente» es solo un script.

Progreso del módulo 0% · 0 de 8
Qué es:

A diferencia de la automatización tradicional (tú conectas cada paso), un agente recibe el resultado deseado y razona, se adapta, hace preguntas y se recupera por sí solo cuando algo falla.

Por qué aprender:

Es la frontera entre «conecta todo a mano» y «di el resultado».

Conceptos clave:

Razona; se adapta; se autocorrige; no determinista.

Qué es:

El asistente como agente personal: investiga, crea archivos, itera sobre el resultado y se vuelve más inteligente con cada uso; todo se ejecuta localmente, sin deploy.

Por qué aprender:

Es la forma más sencilla de agente; construye intuición antes de pasar a la nube.

Conceptos clave:

Local; bajo demanda; observas y aprendes.

Qué es:

El agente ejecuta un workflow, se encuentra con un error, lo diagnostica, corrige la tool y actualiza el workflow para que el error no vuelva a aparecer; las ejecuciones son más fluidas y rápidas.

Por qué aprender:

Es el superpoder de los agentes locales y exactamente lo que desaparece en producción.

Conceptos clave:

Fallar → corregir → actualizar; aprender del fallo; persistir el fix.

Qué es:

Un agente que funciona solo a la hora programada por un patrón cron (5 campos; p. ej., 0 7 * * * = todos los días a las 7 h) — investiga, sintetiza y guarda el resultado, sin que tengas que estar presente.

Por qué aprender:

Es la primera forma de agente que escala más allá de «cuando apareces».

Conceptos clave:

Cron (5 campos); se ejecuta unattended; programa.

Qué es:

Un agente que se activa cuando se llama a un webhook (una URL que escucha datos), recibe un payload: un «timbre digital» que pone el trabajo en marcha.

Por qué aprender:

Es cómo un formulario, una app u otro sistema activa a tu agente.

Conceptos clave:

Webhook = timbre; payload; auth Bearer.

Qué es:

Cuando el agente se ejecuta en la nube según una agenda o un evento, el asistente ya no está supervisándolo para autocorregirse: el sistema se ejecuta, pero no se adapta por sí solo, y un fallo puede pasar desapercibido.

Por qué aprender:

Es el riesgo central en producción; define cómo diseñas el agente.

Conceptos clave:

Sin autocuración; fallas silenciosas; los logs y las alertas cierran la brecha.

Qué es:

Los cuatro requisitos del build unattended: entradas fijas, salida estructurada y predecible, manejo de errores integrado y registro en cada paso — todo desde el 1.er prompt.

Por qué aprender:

Como el agente no se autocura, diseñas la robustez de la salida.

Conceptos clave:

Entradas fijas; salida estructurada; try/catch; registrar todo.

Qué es:

No toda automatización necesita razonamiento: si la tarea es fija y predecible, un script determinista es más barato y confiable que un agente, y esa es una opción válida.

Por qué aprender:

Saber la diferencia evita pagar por una inteligencia que no necesitas.

Conceptos clave:

Determinístico vs. agéntico; «boring is beautiful»; costo vs. adaptación.
