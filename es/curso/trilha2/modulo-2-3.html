MÓDULO 2.3

🔌 MCP por dentro

MCP (Model Context Protocol) es el patrón que le da «brazos» a la IA: una sola conexión expone muchas herramientas de un servicio (enviar, redactar, buscar…), y el agente descubre por sí solo cuáles existen y decide cuál llamar, cuándo y con qué parámetros. En este módulo verás cómo instalar un server y dónde va la clave de API (a mano, en el archivo — nunca en el chat), por qué preferir la configuración por proyecto y cómo diagnosticar y controlar el costo del contexto.

Sin MCP, la IA solo sabe conversar. Con MCP, actúa: lee correos, consulta una base de datos, busca una página en la web, envía un mensaje en Slack. El truco es que no conectas una acción a la vez — conectas un server (un servicio completo, como el correo electrónico), y ya anuncia todas sus herramientas de una vez. El agente ve el menú y elige el plato adecuado para el pedido.

Diagrama ilustrativo — una conexión (el server) proporciona un conjunto de herramientas. El agente lee lo que está disponible y decide, en cada solicitud, qué herramienta usar.

1

🧩 Qué resuelve el protocolo

Qué es

MCP (Model Context Protocol) es un lenguaje común para que la IA se comunique con servicios externos. En vez de conectar una acción a la vez, una sola conexión expone muchas herramientas de ese servicio. Piensa en un servicio de correo electrónico: al conectar el server de correo, el agente obtiene acceso a "enviar", "redactar", "buscar mensaje" — todo a la vez.

¿Qué es?Server MCP — un programita que conecta la IA con un servicio (correo electrónico, base de datos, web), traduciendo lo que entiende cada lado. Herramienta (tool) — una acción concreta que ofrece el server (p. ej., «enviar correo electrónico»), con un nombre y parámetros bien definidos.

El protocolo resuelve el problema de «cómo la IA descubre y usa una acción»: estandariza la descripción de las herramientas. Por eso el agente puede decidir por sí solo cuál herramienta para llamar, cuándo llamar y con qué parámetros. Así es como la IA obtiene "brazos": deja de solo conversar y empieza a actuar en el mundo.

Por qué aprender

Entender MCP es entender de dónde vienen las capacidades de tu agente. Sin eso, parece "magia", y la magia es difícil de depurar. Al saber que cada capacidad es un server con herramientas, sabes qué instalar, qué falta y qué desactivar.

  • •Una conexión, muchas acciones: menos configuración, más capacidad.
  • •Patrón único: el mismo protocolo sirve para correo electrónico, base de datos, web, etc.
  • •Base para lo demás: los siguientes temas solo tienen sentido si esto está bien asentado.

Conceptos clave

1 → N

Una conexión, varias tools.

Brazos de la IA

2

🤖 Cómo el agente descubre y decide

Qué es

En cuanto el agente y el server MCP se conectan, el agente empieza a conocer todas las herramientas disponibles de ese server: nombres, descripciones y parámetros. A partir de ahí, la decisión es suya: describes el resultado en lenguaje natural ("envía un aviso al equipo"), y el agente elige la herramienta adecuada ("enviar mensaje") y completa los parámetros.

¿Qué es?Descubrimiento de herramientas — el momento en que el agente lee el «menú» del server y se entera de lo que puede hacer. Selección de herramienta — el agente razona sobre la solicitud y decide qué tool se ajusta al objetivo.

Diagrama ilustrativo — no dices «usa la tool X». Describes el resultado; el agente compara la solicitud con las herramientas conocidas y elige la mejor.

Por qué aprender

Saber que la decisión es del agente cambia cómo lo pides: te enfocas en el resultado, no en señalar la herramienta. Y cuando elija mal, lo corriges con contexto ("no lo pongas en borrador, envíalo de verdad") en vez de microgestionar. También explica por qué un servidor "encendido pero inútil" sigue siendo un estorbo: sus tools se suman a la lista que el agente debe evaluar.

🎯 Consejo práctico

Si el agente elige la tool equivocada, no le indiques su nombre: aclara el resultado: "quiero que llegue ahora a la bandeja de entrada del cliente, no que quede guardado como borrador". Las descripciones del resultado guían mejor la elección que los comandos.

Conceptos clave

Descubrimiento

Lee el menú al conectarse.

Decisión propia

El agente elige la tool.

Tú → resultado

Describe el "qué".

Parámetros

Lo completa automáticamente.

3

🔑 .mcp.json y la clave en mano

Qué es

Instalar un servidor MCP genera (o edita) un archivo .mcp.json: guarda la configuración del server y, cuando el servicio requiere autenticación, un espacio reservado para la clave de API. La clave en sí la pegas manualmente en el archivo. Nunca en el chat ni le pidas al agente que la ingrese por ti.

¿Qué es?Clave de API (API key) — una contraseña que demuestra que tienes permiso para usar un servicio. .mcp.json — el archivo de configuración que enumera los servers y cómo iniciarlos. Placeholder — el "hueco" donde debe ir la clave, marcado para que lo completes.

🎯 Objetivo: pegar la clave de API manualmente en .mcp.json

.mcp.json (edita el archivo)
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp"],
      "env": {
        "API_KEY": "<cole-sua-chave-aqui>"
      }
    }
  }
}

✅ Cómo verificar: cambia <cole-sua-chave-aqui> con tu clave real, guarda el archivo y reinicia el asistente. La clave queda solo en el archivo local, fuera del historial del chat.

Por qué aprender

Una clave pegada en el chat pasa a formar parte del historial de la conversación, que puede registrarse, compartirse o filtrarse. Si la pegas en el archivo, el secreto queda donde solo tú (y el programa) pueden acceder. Esa es una regla de seguridad, no es una preferencia de estilo: trata cada clave como una contraseña.

✓ Clave en .mcp.json (manualmente)

  • ✓Pegas la clave directamente en el archivo de configuración.
  • ✓El secreto queda en local, fuera del historial de conversación.
  • ✓Controlas quién ve el archivo (y lo excluyes del control de versiones).

✗ Clave en el chat

  • ✗Pegar la clave en un mensaje para el agente.
  • ✗Pedirle a la IA que «inserte la clave» por ti.
  • ✗Dejar la clave en logs, capturas de pantalla o conversaciones compartidas.

Conceptos clave

.mcp.json

Dónde vive la config.

Placeholder

Espacio para la clave.

A mano

Tú la pegas, no la IA.

Nunca en el chat

Clave = contraseña.

4

🏷️ Por proyecto o global

Qué es

La configuración de MCP puede tener dos alcances: global (se aplica a toda la máquina; todos los proyectos pueden verlo) o por proyecto (el archivo .mcp.json está dentro de la carpeta del proyecto y solo se aplica allí). La recomendación es por proyecto: aísla los secretos y el contexto de cada trabajo.

¿Qué es?Alcance global — configuración que se aplica en cualquier lugar de la máquina. Alcance por proyecto — configuración que está en la carpeta del proyecto y solo se aplica mientras trabajas en él. Aislamiento — mantener los secretos y las herramientas de un proyecto separados de los demás.

Diagrama ilustrativo — en el ámbito global, una filtración lo contamina todo; por proyecto, cada trabajo queda en su propia burbuja.

Por qué aprender

La configuración global puede activar un aviso de seguridad en cada reinicio (el programa avisa que hay servidores globales activos para cualquier proyecto). La solución es mover la configuración a la carpeta del proyecto. Por proyecto, también evitas que un cliente «vea» las herramientas y claves de otro: menos riesgo, menos ruido.

🎯 Consejo práctico

¿Te cansaste del aviso de seguridad en cada reinicio? Mueve el bloque de servers de la configuración global al .mcp.json dentro de la carpeta del proyecto. La advertencia desaparece y cada proyecto pasa a incluir solo lo que necesita.

Conceptos clave

Global

Se aplica a toda la máquina.

Por proyecto

Recomendado, aísla.

Aviso al reiniciar

Global puede alertar.

Mover a una carpeta

La corrección del aviso.

5

🔎 Dónde encontrar servers

Qué es

Los servidores MCP están en dos lugares principales: directorios de MCP (sitios que catalogan servidores, como el mcp.so) y en el GitHub (busca "MCP server" + el nombre del servicio que quieres). Antes de instalarlo, busca el server del servicio objetivo; después, sigue su README.

¿Qué es?Directorio de MCP — un catálogo en línea de servers listos, organizado por categoría. GitHub — dónde vive el código de los servers; el README suele incluir el comando de instalación y las variables que hay que completar (como la clave).

Por qué aprender

Saber dónde buscar evita reinventar la rueda: en la mayoría de los casos, el server que necesitas ya existe. Conocer las categorías comunes también agiliza la búsqueda: sabes que existe algo para web scraping, bases de datos, documentos y comunicación, y vas directo.

Categorías comunes de servers

🕸️ Web scraping

Ej.: Firecrawl — leer páginas web.

🗄️ Bases de datos

Ej.: Postgres, Supabase.

📄 Documentos

Ej.: Google Drive, Notion.

💬 Comunicación

Ej.: Slack, Gmail.

🎯 Consejo práctico

Búsqueda rápida: en GitHub, busca MCP server + el nombre del servicio (p. ej.: MCP server notion). Prefiere repositorios con más estrellas y un README claro: suelen estar mejor mantenidos y ser más seguros.

Conceptos clave

Directorios

Catálogos como mcp.so.

GitHub

"MCP server" + servicio.

Categorías

Web, base de datos, docs, chat.

Ya existe

No reinventes la rueda.

🩺 Verificar y diagnosticar

Qué es

El comando /mcp enumera los servers instalados y el estado de cada uno (conectado, con error, etc.). Es la "salud del MCP". Y hay una regla de oro para el diagnóstico: si un server recién instalado no aparece en la lista, reinicia primero el asistente — eso lo resuelve la mayoría de las veces.

¿Qué es?/mcp — comando que muestra los servidores y su estado. Reiniciar — cerrar y abrir el asistente para que vuelva a leer la configuración; muchos servers solo "aparecen" después de eso.

🎯 Objetivo: verificar los servidores MCP conectados

comando (copia y ejecuta)
/mcp

✅ Cómo verificar: la lista muestra cada server y su estado; si no aparece un server nuevo, reinicia el asistente y ejecuta /mcp de nuevo.

La secuencia completa, paso a paso

1

Instalar el servidor

Búscalo en el directorio/GitHub y sigue el README. Eso genera o edita el .mcp.json.

2

Revisar la configuración

Ve el bloque del server en el .mcp.json (preferiblemente por proyecto).

3

Pegar la clave manualmente

Reemplaza el placeholder por la clave de API — en el archivo, nunca en el chat.

4

Reiniciar el asistente

Cierra y vuelve a abrir para releer la configuración y cargar el server.

5

Verificar con /mcp

Ejecuta /mcp; el server debe aparecer conectado. Si no, vuelve al paso 4.

Por qué aprender

Sin el /mcp, te quedas a oscuras: no sabes si el server se conectó, falló o ni siquiera se leyó. Y sin el hábito de reiniciarlo, pierdes tiempo «arreglando» lo que no está roto. Reiniciarlo es el primer paso de cualquier troubleshooting de MCP: barato, rápido y casi siempre suficiente.

Conceptos clave

/mcp

Lista los servers + su estado.

Estado

¿Conectado? ¿Con error?

Reiniciar primero

Resuelve en la mayoría de los casos.

¿No apareció?

Reinicia y ejecuta /mcp.

💸 Costo de contexto

Qué es

Cada server activo inyecta las definiciones de tus herramientas en contexto de la IA — y eso consume tokens. Muchos servers conectados significan más texto que el modelo debe leer antes de responder, aunque no uses ninguno. La regla: desactiva los servidores que no estés usando para liberar contexto.

¿Qué es?Contexto — todo lo que la IA «tiene en la cabeza» durante la conversación (tu mensaje + instrucciones + definiciones de herramientas). Token — fragmento de texto que cuenta el modelo; más texto = más tokens = más costo y más ruido.

Diagrama ilustrativo — cada server conecta un bloque de definiciones. Menos bloques = más espacio para que la IA piense, menos costo y menos ruido.

Por qué aprender

Un contexto saturado tiene tres costos: consume más tokens (es más caro), confunde al agente (más herramientas que evaluar = más posibilidades de elegir mal) y hace que todo sea más lento. Mantener activos solo los servers del trabajo actual es la forma más sencilla de reducir costos y errores de una vez.

✓ Desactiva los servers que no uses

  • ✓Mantén activos solo los servers del trabajo actual.
  • ✓Libera contexto: menos tokens, menos costo.
  • ✓Menos herramientas para evaluar = elecciones más acertadas.

✗ Déjalos todos siempre activados

  • ✗Acumular servers que ni siquiera usas en ese proyecto.
  • ✗Pagar tokens por definiciones de herramientas inactivas.
  • ✗Más ruido = más posibilidades de que el agente se equivoque de tool.

🎯 Consejo práctico

Haz una «limpieza» periódica: ejecuta /mcp, revisa la lista y desactiva (o elimina del .mcp.json) todo lo que no sea del proyecto actual. Menos ruido = menos errores + menor costo.

Costo de tokens
