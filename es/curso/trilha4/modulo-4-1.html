MÓDULO 4.1

📦 Skills: concepto y anatomía

Una skill es un archivo de instrucciones que se convierte en un comando reutilizable: describes un proceso una vez y el agente empieza a ejecutarlo siempre de la misma manera, sin que tengas que volver a explicarlo. Conceptualmente es la capa W (workflows) del framework WAT, solo que vive en una carpeta y se activa con un slash command. Aquí entiendes qué es una skill, dónde vive, cuál es su anatomía y cuándo tiene sentido crear una en vez de solo escribir.

Antes de los siete temas, mira el camino que conecta todo: escribes un workflow en Markdown, pasa a vivir en una carpeta (.claude/skills), y el agente lo expone como un slash command que puedes invocar cuando tú (o una instrucción) lo llamas. Una skill es, en esencia, un proceso empaquetado para reutilizarlo.

1

📦 Qué es una skill

Qué es

Una skill es, en esencia, un archivo markdown de instrucciones — conceptualmente idéntico a la capa W (workflows) del framework WAT. La diferencia respecto de un workflow que solo describes en el chat es dónde está e cómo se activa: la skill queda guardada en una carpeta del proyecto y se invoca con un comando, así que puedes ejecutarla de la misma forma tantas veces como quieras, sin tener que reescribir el proceso.

¿Qué es?Workflow — una secuencia de pasos que resuelve una tarea (la «W» de WAT). Comando slash — un comando que empieza con / y activa una acción en el agente (p. ej., /clear). Una skill es un workflow empaquetado y expuesto como slash command.

El detalle que lo libera todo: no necesitas saber escribir skills. Describes el workflow en lenguaje natural —"cada vez que te lo pida, haz X, luego Y y después guárdalo en Z"— y le pides al agente que convertir esto en una skill / slash command. Crea el archivo y luego puedes invocarlo con un comando. Es el mismo principio del vibe coding: describes el resultado y la IA hace el trabajo pesado.

Por qué aprender

Las skills resuelven cuatro problemas de una sola vez. Sin ellas, vuelves a explicar el mismo proceso en cada sesión, gastas tokens repitiendo contexto y pierdes consistencia. Al empaquetarlas en una skill, obtienes:

  • •Consistencia: el mismo proceso se ejecuta igual cada vez, sin tener que volver a explicarlo.
  • •Ahorro de tokens: la skill carga bajo demanda, solo cuando se invoca: no ocupa el contexto todo el tiempo.
  • •Compartible: es un archivo: se lo pasas a todo el equipo.
  • •Confiable: agrupa pasos complejos y fáciles de olvidar → delegas y te olvidas.

🎯 Objetivo: pedirle al agente que convierta uno de tus workflows en una skill

prompt para el agente (cópialo y edítalo)
Transforme este workflow numa skill chamável (slash command).

Nome desejado: <nome-da-skill>
Quando deve ser usada: <descreva o gatilho — ex.: "quando eu pedir um resumo de reunião">
Argumentos que ela recebe: <ex.: texto-bruto, formato-de-saida>

1. <passo 1>
2. <passo 2>
3. <onde salvar / formato final>

Crie o arquivo em .claude/skills/ e me diga como invocá-la.

✅ Cómo verificar: el agente debe crear el archivo y responder con el comando /<nome-da-skill>. Ejecútalo una vez para confirmar que aparece y solicita los argumentos.

📁 Dónde viven y cómo se convierten en slash command

Qué es

Las skills viven en un directorio del proyecto llamado .claude/skills. La organización es simple: cada skill está en su propia carpeta, y dentro de ella hay un archivo de skill que describe lo que hace. El agente recorre esa carpeta y expone cada skill como un slash command — un comando que empieza con / y que escribes para activarla.

¿Qué es?Directorio .claude — una carpeta de configuración que el agente lee dentro de tu proyecto. Built-in — un comando que ya viene listo (ej.: /clear limpia el contexto). Tus skills aparecen junto a los built-ins, en la misma lista de slash commands.

Por qué aprender

Entender el lugar y el mecanismo acaba con la magia: una skill no es una función oculta de la IA, es un archivo en una carpeta que se convierte en comando. Cabe destacar la unificación reciente: los slash commands se unificaron en skills — es decir, crear una skill y crear un slash command se convirtieron en lo mismo. Por eso, comparar con built-ins como /clear ayuda: la única diferencia es que los tuyos los defines tú, en el proyecto.

Ciclo de vida de una skill

  1. 1

    Describir el workflow

    Cuentas el proceso en lenguaje natural: pasos, entradas, salida.

  2. 2

    El agente genera el archivo de skill

    Crea la carpeta en .claude/skills con nombre, descripción y pasos.

  3. 3

    Invocar mediante el comando slash

    Tú escribes /nome-da-skill y el agente ejecuta el proceso.

  4. 4

    Reutilizar (y compartir)

    Siempre la misma ejecución; y, como es un archivo, va junto con el proyecto para el equipo.

3

🧬 Anatomía del SKILL.md

Qué es

Toda skill tiene cuatro partes esenciales: nombre (cómo se llama), descripción (o disparador — le enseña al agente CUÁNDO usar la skill), argumentos esperados (las entradas que recibe) y las instrucciones paso a paso (qué hacer). La pieza más subestimada es la descripción: no es decorativa; es lo que hace que el agente decida por sí solo que esa skill es la adecuada para la situación.

¿Qué es?Disparador (trigger) — la condición que hace que se elija la skill. Una buena descripción dice «usa esto CUANDO...». Si es vaga, el agente no sabrá cuándo aplicarla; si es precisa, acertará por sí solo.

🎯 Objetivo: crear el archivo que define una skill invocable

.claude/skills/draft-email/SKILL.md (copia y edita)
---
name: <nome-da-skill>
description: <quando-acionar — ex.: rascunhar um e-mail a partir de bullets>
---

# <Título da skill>

## Argumentos
- destinatario: <quem recebe>
- tom: <profissional | casual>
- bullets: <pontos-chave do e-mail>

## Passos
1. Leia os <bullets> e o <tom>.
2. Escreva um e-mail polido, conciso, sem enrolação.
3. Salve em temporary/<nome-arquivo>.md

✅ Cómo verificar: ejecuta /<nome-da-skill> — si la skill aparece en la lista de slash commands y pide los argumentos que faltan, está registrada.

Por qué aprender

Conocer la anatomía te da control incluso sin escribir: sabes pedir una buena descripción que active el agente ("úsalo cuando pegue viñetas de correo electrónico"), nombrar argumentos claros y enumerar los pasos en el orden correcto. Y sabes revisar lo que generó el agente: si la descripción es poco clara, solo tienes que pedir que la haga más específica. La estructura frontmatter (nombre + descripción) + cuerpo (argumentos + pasos) es el esqueleto de toda skill.

4

🔧 Las Skills pueden llamar tools

Qué es

Una skill no reemplaza las tools (herramientas) — ella las orquesta. Dentro de tus pasos, una skill aún puede activar tools: scripts en Python que buscan en la web, extraen datos de una página o generan un documento. Es decir, el WAT permanece intacto por debajo: la skill es el W (workflow), la tool es el T (herramienta), y el agente decide cuándo ejecutar cada tool durante el proceso.

¿Qué es?Tool (herramienta) — un fragmento de código que realiza una acción concreta en el mundo (búsqueda, scraping, guardar un archivo). WAT — el framework Workflows + Agents + Tools: las skills son los workflows, las tools son las herramientas, el agente lo conecta todo.

Por qué aprender

Saber que skill ≈ W y tool ≈ T evita una confusión común: creer que adoptar skills descarta todo lo que aprendiste sobre tools y MCP. No es así. La skill solo da un guion reutilizable sobre cuándo y cómo usar tus herramientas. Una skill de "investigación de mercado", por ejemplo, puede decir: busca en la web, extrae el contenido de las tres primeras páginas, haz un resumen y genera un documento — llamando a una tool en cada paso.

⚖️ Cuándo usar una skill vs escribir

Qué es

No todo merece convertirse en una skill. La regla: crea una skill cuando el proceso se repite, la consistencia importa, las instrucciones son complejas o fáciles de olvidar, o quieres compartirla con el equipo. Para lo demás —una tarea de una frase, una experimentación inicial, una instrucción sencilla— es más rápido simplemente escribirlo. Empaquetar una tarea trivial en una skill solo agrega ceremonia.

¿Qué es?Ceremonia — el esfuerzo extra de formalizar algo (crear un archivo, ponerle nombre, documentar). Vale la pena cuando lo vas a reutilizar; es un desperdicio para un pedido único.

Por qué aprender

El criterio evita los dos extremos: nunca usar skills (y tener que volver a explicarlo todo cada vez) o convertir cualquier cosa en una skill (y llenar la carpeta de comandos que usas una sola vez). La pregunta clave es sencilla: "¿voy a repetir esto?" Si es así y la consistencia importa, conviene usar una skill. Si es algo puntual, escríbelo.

✓ Crea una SKILL cuando…

  • ✓El workflow se repite (ya lo hiciste 3+ veces).
  • ✓La consistencia importa (siempre el mismo formato y calidad).
  • ✓Las instrucciones son complejas o fáciles de olvidar.
  • ✓Quieres compartir el proceso con el equipo.

✗ Solo ESCRIBE cuando…

  • ✗Es una tarea puntual de una sola frase.
  • ✗Todavía estás experimentando / explorando el problema.
  • ✗La instrucción es simple y no se repite.
  • ✗Formalizar costaría más que simplemente volver a pedirlo.

Repetición

Si se repite → skill.

Consistencia

Importa → skill.

One-off

6

🪶 Skills vs CLAUDE.md (contexto bajo demanda)

Qué es

La división del trabajo: el CLAUDE.md guarda solo lo que sirve para cada sesión — propósito del proyecto, objetivo, framework, reglas generales. Está siempre en el contexto. En cambio, lo que es por tarea (por tarea) va a skills, que cargan bajo demanda — solo cuando invocas ese comando. Es la diferencia entre «lo que la IA necesita saber siempre» y «lo que solo necesita cuando va a hacer X».

¿Qué es?CLAUDE.md — archivo de memoria que el agente lee al inicio de cada sesión. Contexto bajo demanda — cargar información solo cuando se necesita, para no ocupar todo el tiempo la "memoria de trabajo".

Diagrama ilustrativo — poner todo en CLAUDE.md llena el contexto fijo; mantener el contenido por tarea en skills deja decenas de comandos disponibles sin ocupar espacio, porque solo se carga el que invocas.

Por qué aprender

El error clásico de principiante es meter todo en CLAUDE.md — toda instrucción, todo workflow, cada detalle. Eso se desborda el contexto: el archivo se vuelve enorme, ocupa espacio en cada sesión y reduce la atención de la IA. La clave de las skills es precisamente esta: puedes tener 20, 50 skills sin sobrecargar nada, porque solo se cargan cuando se invocan. CLAUDE.md conciso + muchas skills bajo demanda > CLAUDE.md gigante.

✓ En CLAUDE.md (toda sesión)

  • ✓Propósito y objetivo del proyecto.
  • ✓El framework / las convenciones generales.
  • ✓Reglas que se aplican en cualquier tarea.

✗ NO en CLAUDE.md → va a una skill

  • ✗Workflows específicos para una sola tarea.
  • ✗Paso a paso largo y detallado de un proceso.
  • ✗Todo lo que solo importa cuando vas a hacer X.

🎯 Consejo práctico

Antes de agregar algo al CLAUDE.md, pregunta: "¿esto aplica a todas las sesiones o solo cuando hago una tarea específica?" Si es específico, conviértelo en una skill. Tu CLAUDE.md debe poder revisarse de un vistazo; el resto del conocimiento vive en la carpeta de skills, listo para usarse.

🤝 Compartir y versionar

Qué es

Como una skill es solo un archivo en una carpeta del proyecto, hereda todas las ventajas de un archivo de código: puede ser con control de versiones en Git (historial de cambios, revisión, revertir), y compartida con cualquier persona que clone el proyecto. El proceso deja de ser conocimiento atrapado en la cabeza de una persona y se convierte en un activo del equipo.

¿Qué es?Git — el sistema que guarda el historial de versiones de los archivos. Versionar — registrar cada cambio de un archivo a lo largo del tiempo para poder verlo, revisarlo y revertirlo. Como la skill es un archivo, entra en este flujo sin costo adicional.

Por qué aprender

Este es el salto de «truco personal» a «capacidad del equipo». Cuando tu mejor workflow se convierte en una skill versionada, cualquier colega puede ejecutar el mismo proceso, con la misma calidad, sin tener que preguntarte cómo. Las correcciones de errores en la skill benefician a todos en la siguiente invocación. Es reutilización de verdad: lo escribes una vez y todo el equipo se beneficia.

Conceptos clave

Es archivo

Ligero y versionable.

Git

Historial y revertir.

Compartible

Si lo clonaste, ya lo tienes.

Recurso del equipo

No te quedes atrapado en una sola perspectiva.
