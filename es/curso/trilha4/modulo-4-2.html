MÓDULO 4.2

🔨 Construcción práctica de Skills

Dejando atrás la teoría: aquí crea skills de verdad, desde cero, con la misma mentalidad de vibe coding: tú describes el workflow y el agente escribe el SKILL.md en el formato oficial y se convierte en un slash command que reutilizas cuando quieras. Vamos a crear una skill para redactar correos electrónicos, probarla, invocarla sin argumentos, reutilizarla con el contexto limpio y luego combinarla con una skill de diseño lista para usar. Cada tema es un build que se puede copiar.

🔧 Antes de empezar

Una skill es un procedimiento reutilizable que enseñas una vez y llamas cuando quieras. En el módulo 4.1 viste la anatomía (el archivo SKILL.md con nombre, descripción e instrucciones). Aquí tú construye. No escribas el SKILL.md a mano: describe qué hace la skill y pídele al agente que la genere en el formato oficial. La misma mentalidad de vibe coding: describes el resultado y el agente hace el trabajo técnico.

Toda skill nace del mismo ciclo: tú describe el workflow en lenguaje natural, el el agente genera el SKILL.md en el formato oficial, se convierte en un slash command (p. ej., /draft-email), y a partir de ahí tú vuelve a usar — de preferencia con el contexto limpio, para que cada ejecución sea predecible.

Diagrama ilustrativo — el recuadro azul es el agente escribiendo el SKILL.md. Construir se hace una vez; reutilizar, para siempre. El lazo punteado representa la reutilización con /clear entre ejecuciones.

1

📝 Pedir una skill en el formato oficial

Qué es

Crear una skill comienza con una buena solicitud. Tú describe el workflow — cuáles son las entradas, cuál es el comportamiento esperado, y dónde guardar el resultado —y le pide al agente que lo convierta en un slash command siguiendo el formato oficial de skill. Es la misma mentalidad del vibe coding: tú dices el «qué» y el agente escribe el SKILL.md (el «cómo»).

¿Qué es?Formato oficial — la estructura estándar de una skill: un archivo SKILL.md con nombre, descripción (cuándo usarla) y instrucciones. Comando slash — un atajo del tipo /nome que activa la skill. Plan Mode — modo en el que el agente planifica antes de modificar archivos; es ideal para revisar la skill antes de crearla.

Una buena solicitud es específica en las tres dimensiones. Si es demasiado vaga («haz una skill de correo electrónico»), obliga al agente a adivinar; si es demasiado específica sobre los pasos técnicos («crea un archivo .md con YAML frontmatter que contenga…»), desperdicia la ventaja de dejarlo elegir. El punto justo: describe las entradas, el comportamiento y el destino, y deja que se encargue del resto.

🎯 Objetivo: pedirle al agente que cree una skill y revisar el plan antes de guardarlo.

prompt (pégalo en el chat del agente)
Entre em Plan Mode.

Quero uma skill que .
- Entradas: 
- Comportamento: 
- Onde salvar: 

Crie isso como um slash command seguindo o formato
oficial de skill (SKILL.md com nome, descrição e
instruções). Me mostre o plano antes de gravar.

✅ Cómo verificar: el agente responde con un plan (nombre del comando, descripción, instrucciones) y pregunta qué falta, en vez de crear archivos de inmediato. Apruébalo y guardará el SKILL.md.

Por qué aprender

Una solicitud en el formato oficial garantiza que la skill nazca reutilizable, con nombre, descripción e instrucciones que el agente volverá a leer cada vez que la invoques. Pedirla en Plan Mode te da un punto de revisión: corriges el alcance antes de que se convierta en un archivo.

✓ Buena solicitud de skill

  • ✓Di las entradas, o comportamiento e dónde guardar.
  • ✓Pide el formato oficial (slash command / SKILL.md).
  • ✓Revisa el plan antes de guardar (Plan Mode).

✗ Solicitud deficiente

  • ✗"Crea una skill de correo electrónico" (sin entradas ni destino).
  • ✗Indicar el YAML y la estructura del archivo paso a paso.
  • ✗Dejar que el agente escriba sin que revises el alcance.

2

✉️ Skill "redactar correo" (/draft-email)

Qué es

Vamos a construir la primera skill de verdad: /draft-email. Recibe tres entradas: los viñetas del contenido, el destinatario e o tono — y escribe un correo pulido y conciso, sin rodeos (fluff). El borrador se guarda en una carpeta temporal y todo el procedimiento se convierte en el comando /draft-email.

¿Qué es?Viñetas — los puntos principales que el correo electrónico debe cubrir (no escribes frases, solo temas). Tono — el estilo de escritura (formal, amigable, directo). Sin relleno — sin frases de relleno; solo lo esencial, de forma educada y clara.

🎯 Objetivo: o SKILL.md que el agente genera para la skill /draft-email.

SKILL.md (formato oficial)
---
name: draft-email
description: Rascunha um e-mail polido a partir de
  bullets, destinatário e tom. Use quando o usuário
  pedir para escrever ou rascunhar um e-mail.
---

# Rascunhar e-mail

## Entradas
- destinatário: para quem é o e-mail
- tom: 
- bullets: os pontos a cobrir

Se faltar alguma entrada, PERGUNTE antes de escrever.

## Comportamento
1. Escreva um e-mail conciso e polido, sem fluff.
2. Respeite o tom pedido; assunto curto e claro.
3. Salve o rascunho em /email.md.

✅ Cómo verificar: invoca /draft-email con un destinatario, un tono y 2-3 viñetas. El agente debe devolver un correo conciso, con el tono adecuado, y guardar el archivo. Léelo: ¿tiene asunto? ¿está libre de relleno?

Por qué aprender

El correo electrónico es el ejemplo perfecto de tarea repetitiva y estandarizable: escribes decenas por semana y todos siguen la misma estructura. Encapsular esto en una skill significa que el «cómo escribir bien» queda en el SKILL.md, y tú solo proporcionas el contenido. Constrúyelo una vez y ahorra tiempo para siempre.

🎯 Consejo práctico

Después de construir, prueba de inmediato con un caso real tuyo. Si el tono sale mal o el correo queda demasiado largo, no empieces de nuevo: da feedback ("quedó demasiado formal, hazlo más directo") y pide ajustar el SKILL.md. La skill mejora con cada uso.

Conceptos clave

3 entradas

Destinatario, tono, viñetas.

Conciso

Pulido y sin relleno.

Guarda

En una carpeta temporal.

/draft-email

Se convierte en comando slash.

3

❓ Invocar sin argumentos

Qué es

La prueba de robustez de una buena skill: llama a /draft-email sin enviar ningún dato. En vez de ejecutarse a ciegas e inventar un destinatario y un tono, la skill debe preguntar sobre los datos que faltan —destinatario, tono, bullets— antes de escribir una sola línea. Esa instrucción de SKILL.md ("si falta algún dato, PREGUNTA") es lo que garantiza eso.

¿Qué es?Ejecutarse a ciegas — cuando el agente adivina datos que no le diste y produce algo que no era lo que querías. Skill robusta — una skill que se niega a ejecutarse si faltan datos; primero los recopila y después se ejecuta.

Diagrama ilustrativo — invocar sin datos no es un error: activa la recopilación. La skill solo escribe después de tener las tres entradas.

Por qué aprender

Las skills que preguntan antes de ejecutarse evitan la peor pesadilla de la automatización: un resultado plausible pero incorrecto, basado en suposiciones. Cuando la skill recopila lo que falta, tú controlas la entrada y nunca recibes un correo dirigido a la persona equivocada y con el tono equivocado.

🎯 Objetivo: ver cómo la skill solicita los datos de entrada en lugar de adivinarlos.

comando + respuesta esperada de la skill
Você:
/draft-email

Skill (esperado):
Para escrever o e-mail, preciso de:
1) Para quem é? 
2) Qual o tom? 
3) Quais pontos cobrir? 

(a skill NÃO escreve nada até você responder)

✅ Cómo verificar: si la skill ya genera un correo genérico sin preguntar, está trabajando a ciegas. Vuelve a SKILL.md y refuerza la regla «si falta información de entrada, PREGUNTA primero».

Conceptos clave

Robusta

Tú controlas

4

🔁 Reutilizar con contexto limpio

Qué es

El verdadero retorno de crear una skill se ve al reutilizarla. Para reutilizarla bien, dale /clear (limpia la conversación) y llama a /draft-email de nuevo con nuevas entradas. El resultado: una salida fresca y consistente, siguiendo las mismas reglas del SKILL.md, sin que la basura de la conversación anterior contamine el nuevo correo.

¿Qué es?/clear — comando que borra el contexto de la conversación (el agente «olvida» lo que se dijo antes). Contexto limpio — empezar desde cero, sin que los borradores antiguos influyan en el nuevo. Conversación inflada — cuando el historial acumulado hace que el agente mezcle pedidos y pierda consistencia.

Por qué aprender

Sin un contexto limpio, el tercer correo del día puede heredar el tono del primero o mencionar al destinatario equivocado. Limpiar antes de cada reutilización hace que cada ejecución previsible — la skill aplica siempre las mismas reglas, partiendo siempre del mismo punto.

✓ Reutiliza correctamente (contexto limpio)

  • ✓Dar /clear antes de cada nueva ejecución.
  • ✓Pasar las nuevas entradas explícitamente.
  • ✓Confiar en las mismas reglas de SKILL.md cada vez.

✗ Reutilizar mal (conversación inflada)

  • ✗Acumular correos electrónicos en la misma conversación larga.
  • ✗Dejar que el tono/destinatario anterior se filtre en el nuevo.
  • ✗Resultados imprevisibles por el contexto acumulado.

🎯 Objetivo: volver a usar la skill desde cero, con nuevas entradas.

secuencia de comandos (copia y ejecuta)
/clear

/draft-email
destinatário: 
tom: 
bullets:
- 
- 
-

✅ Cómo verificar: el nuevo correo debe reflejar SOLO las entradas nuevas, sin rastros del correo anterior. Repite con otras entradas y compara: la estructura es consistente y el contenido es nuevo.

Sin residuos antiguos.

5

📊 Skill "documento → diapositivas"

Qué es

Una skill más ambiciosa, pero construida del mismo modo: documento → diapositivas. Lee un documento, extrae los puntos clave y crea una presentación profesional usando herramientas Python. El documento de entrada queda en temporary/resources y la presentación generada sale en temporary/outputs — carpetas organizadas, entrada separada de salida.

¿Qué es?Herramientas de Python — el agente ejecuta código Python para generar el archivo de diapositivas (la skill describe qué, el agente escribe el código). resources / outputs — convención de carpetas: las entradas en resources, resultados en outputs, para no mezclar.

🎯 Objetivo: crear la skill que convierte un documento en una presentación.

prompt de creación (pégalo en el chat)
Crie uma skill chamada  que:
- Lê um documento de temporary/resources/
- Extrai os pontos-chave do conteúdo
- Cria uma apresentação profissional usando
  ferramentas Python
- Salva o resultado em temporary/outputs/

Faça no formato oficial (slash command). Se faltar
o arquivo de entrada, PERGUNTE qual usar.

✅ Cómo verificar: coloca un documento en temporary/resources, invoca la skill y revisa temporary/outputs — debe existir un archivo de presentación con los puntos clave del documento, no el texto en bruto copiado.

Por qué aprender

Esta skill muestra que el mismo patrón escala: entradas claras, comportamiento descrito, destino definido — ahora con el agente escribiendo código Python por debajo. No necesitas saber Python; necesitas describir el resultado. Y la separación resources/outputs mantiene el proyecto limpio y la skill reutilizable con cualquier documento.

Conceptos clave

Entrada en resources.

Puntos clave

Extrae lo esencial.

Tools de Python

Salida separada.

6

🎨 Conectar una skill de diseño lista

Qué es

Skills se componen. En vez de describir cada detalle visual de tu presentación, tú apila una skill de diseño ya existente sobre la skill doc-to-slides. La skill de diseño carga las reglas de tipografía, colores y espaciado; tu skill se encarga del contenido. El resultado mejora visualmente sin que te conviertas en diseñador.

¿Qué es?Composición — combinar dos skills para que una use la otra (contenido + diseño). Acumular — agregar una skill al flujo sin reescribir la primera; cada una hace su parte. Skill de diseño lista — una skill ya creada (tuya o de la comunidad) que aplica un patrón visual.

Diagrama ilustrativo — agregar una skill de diseño no reemplaza la tuya; cada una cubre una responsabilidad y juntas mejoran el resultado.

Por qué aprender

La composición es lo que hace que tu biblioteca de skills valga más que la suma de sus partes. Una skill de diseño lista para usar se convierte en un "tema" que puedes integrar en cualquier skill que genere un artefacto visual. Reutilizas conocimiento de diseño que ni siquiera es tuyo — y el resultado parece hecho por un especialista.

🎯 Consejo práctico

Mantener skills pequeñas y con una sola responsabilidad (una crea contenido, otra diseña). Las skills concisas se combinan mejor: es más fácil juntar dos piezas enfocadas que desmontar una skill gigante que intenta hacerlo todo. Piensa en piezas de Lego, no en un bloque macizo.

Conceptos clave

Componer

Las skills se combinan.

Acumular

Diseño por encima del contenido.

Reutilizar

Skill lista = tema.

Enfoque único

Cada skill hace una cosa.

📚 Biblioteca de skills del alumno

Qué es

Ahora que sabes construir, probar, invocar y reutilizar, el paso final es acumular: crear tu biblioteca de skills. Cada skill es una tarea repetitiva tuya, encapsulada una sola vez. Abajo encontrarás un catálogo de ideas listas, no para copiar, sino para que te sirvan de punto de partida de tu propia colección.

¿Qué es?Biblioteca de skills — el conjunto de slash commands que fuiste creando, cada uno automatiza una tarea que antes hacías a mano. Cuantas más skills buenas tengas, más aprovechas el esfuerzo: lo describes una vez y lo reutilizas durante meses.

El ciclo de vida de una skill

  1. 1
    Construir

    Describe el workflow; el agente genera el SKILL.md en el formato oficial.

  2. 2
    Probar

    Ejecútala con un caso real; invócala sin args para comprobar que pregunta.

  3. 3
    Reutilizar

    /clear + nuevas entradas → salida fresca y consistente, mil veces.

  4. 4
    Modificar / componer

    Da feedback para ajustar el SKILL.md, o añade otra skill encima.

Por qué aprender

Una biblioteca de skills es capital que genera intereses: cada skill que creas ahorra tiempo en cada ejecución futura, y las buenas skills se combinan en flujos más grandes. Empieza poco a poco —con una o dos skills para tus tareas más repetitivas— y deja que la colección crezca con el uso.
